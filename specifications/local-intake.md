# Temporary local intake for requested credentials

A missing server credential must have a usable, bounded setup path. A request in the original credential store, registered holder recipients and explicit host-owned input policy precede intake. This module performs custody only; saving never admits provider authority or service access.

The original HTTP server and bounded JSON body reader supply transport. Bind only 127.0.0.1 on an ephemeral port. A random one-use fragment capability authenticates details and the sole JSON write. Exact Host and POST Origin, nonce CSP, no-store, no-referrer, bounded body and key length, one in-flight write, expiry and completion shutdown protect the local boundary. Do not accept account passwords through a service-key form. The caller owns provider instructions, metadata and registered holder selection.

Use the original encrypted store.put writer. Do not introduce plaintext files, logs, browser storage, telemetry, retention, host configuration or a permanent daemon. Intake refuses an already held credential. Its checks do not assert cross-process transactional exclusion: callers must not run competing intake instances for the same request.

Seven native behavioral tests cover encrypted write/read, refusal boundaries, body limits, one-use completion, concurrency, expiry, cancellation and failure. The initial Gemini 3.1 candidate (vU6scbVquF1iKsPN4o6dzw5iOtF4e3wCiNH5OuIH9Ao) was rejected for incorrect custody/server contracts and unsafe control flow. The received implementation was rewritten by the host engineer. Provider key verification, billing deployment and customer acceptance remain separate.
